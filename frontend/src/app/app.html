Operational Flow Breakdown

How the Architecture Operates: 5 Defense-in-Depth Stages

🚫
CRITICAL ENTERPRISE POLICY: NO DIRECT FILE-TO-ERP PATH
Untrusted external files received from customer CRMs (Salesforce) never bypass guardrail inspection. Azure AI Content Safety verifies document content and extracted fields in-flight before downstream SAP S/4HANA persistence or transaction execution.
Stage 1

Salesforce Multipart Ingestion

Salesforce Opportunity or Order updates trigger an Apex webhook transmitting multi-format attachments (PDF, JSON, TXT). Ingests orders ranging from 1-page standard parts to 22-page mega procurement agreements.

Stage 2

Serverless Function Orchestration

Azure Function HTTP Trigger (SalesforcePurchaseOrderIngest) receives multipart streams, verifies origin authenticity, streams binary payloads to Content Understanding, and manages in-flight guardrail gating.

Stage 3

Azure AI Content Understanding

Multimodal vision-language layout models and natural language extraction instructions extract key schema fields (PO Number, Date, Parties, 120+ Line Items, Incoterms, and Special Instructions) without custom training.

Stage 4

Azure AI Content Safety Guardrails

Extracted fields and delivery instructions are evaluated in-flight: Prompt Shield blocks indirect injections, PII Shield redacts personal cards/SSNs, and custom blocklists enforce ITAR/EAR export controls.

Stage 5

Conditional SAP S/4HANA Routing

Clean orders are transmitted to SAP S/4HANA via OData/RFC BAPI for automated sales order posting. High-value orders (> $100K) route to managerial review. Violations are quarantined with SOC alerts.

🟣
HashiCorp Terraform Infrastructure

Declarative Infrastructure as Code deploying App Service (caldova-showcase-plan), Cognitive Services (AIServices), and Managed Identity with zero hard-coded credentials.

📊
Azure Observability & Telemetry

Full distributed transaction tracing across Azure Monitor, Application Insights, and Log Analytics, correlating Salesforce webhook IDs with Content Safety risk scores and SAP RFC results.

📑
Large-Context 22-Page Protection

250-token recursive windowing with 50-token rolling overlap ensures prompt attacks or PII straddling token boundaries in 10+ to 22+ page contracts cannot escape detection (Max Severity Synthesis).

Key Architectural Clarifications (Customer & Technical Questions)

Addressing core questions from customer technical reviews regarding Azure AI services, deployment models, and guardrails.

Document Intelligence vs. Azure Content Understanding

While both services extract data from documents, they serve distinct architectural tiers:

Azure Document Intelligence

Structured OCR & Document Layout

  • Core Specialization: High-throughput deterministic extraction of printed & handwritten documents, forms, receipts, invoices, IDs, and tax documents.
  • Extraction Technique: Layout analysis, bounding box coordinate tracking, tabular hierarchy reconstruction, and key-value pair detection.
  • Model Customization: Custom template models and custom neural models trained on labelled PDF/TIFF samples.
  • Optimal Use Case: Standardized invoice layouts where exact pixel-level coordinate alignment and schema rigidity are paramount.
Azure AI Content Understanding

Multimodal Generative Extraction & Reasoning

  • Core Specialization: Broader multimodal understanding spanning documents, images, video recordings, audio transcripts, and unstructured text.
  • Extraction Technique: Combines state-of-the-art vision-language models with natural language extraction prompts and user-defined schemas.
  • Model Customization: Zero-shot / few-shot prompt instructions; understands complex semantic intent, reasoning, and context variations without extensive manual annotation.
  • Optimal Use Case: Diverse Salesforce purchase order packages with irregular supplier formatting, embedded instructions, and unstructured notes.

Azure AI Foundry Requirement & Resource Deployment Model

Clarification on whether Content Understanding requires an Azure AI Foundry resource or can operate standalone.

Confirmed Architectural Fact

Azure AI Content Understanding is powered by Azure AI Services (Foundry Hub)

Content Understanding is provisioned through Azure AI Services (ARM resource type Microsoft.CognitiveServices/accounts with kind AIServices). In Azure AI Foundry, this represents the foundational multi-service account.

Deployment Model A: Unified Foundry Project (Recommended)

Content Understanding is provisioned within an Azure AI Foundry Project. This enables single-pane-of-glass governance, centralized RBAC (Cognitive Services OpenAI Contributor), tracing, and unified connection endpoints (https://<hub>.services.ai.azure.com).

Deployment Model B: Standalone Cognitive Service REST API

Applications (such as our Azure Function) can invoke Content Understanding directly using the Azure Cognitive Services regional endpoint and API Key or Managed Identity, without strictly requiring the Azure AI Foundry portal UI once the resource is provisioned.

Large-Context Handling & Sliding Window Best Practices

For enterprise high-volume orders, 10-page catalog contracts (Scenario 6), and 22-page ultra-large master purchase agreements (Scenario 7), Content Safety enforces token limits and sliding windows.

1. Recursive Document Chunking

Long documents are broken into 250-token semantic chunks with a 50-token rolling overlap to prevent injection keywords from splitting across chunk boundaries.

2. Parallelized Guardrail Scanning

Chunks are submitted concurrently to Azure AI Content Safety Prompt Shield and text analysis endpoints, keeping end-to-end latency below 500ms.

3. Max-Severity Risk Synthesis

Any individual chunk containing an injection payload or high-severity violation triggers document quarantine, protecting downstream enterprise systems.
